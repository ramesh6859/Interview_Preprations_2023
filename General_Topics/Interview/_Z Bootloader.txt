01.	What is a bootloader, and why is it used in Embedded systems?
	1.	Code running at power-on to initialize the system and load the app.
	2.	Initialization: Sets up hardware (clocks, memory).
	3.	Firmware Update: Enables updates without external hardware.
	4.	Secure Boot: Verifies firmware integrity.
	
02.	What is the purpose of a bootloader in Embedded systems, and how is it implemented?
	1.	Purpose: Loading firmware, hardware init, updates via UART/USB/I2C.
	2.	Implementation: Resides in reserved flash memory; designed to be small and robust.
	
03.	What are bootloaders, and how are they related to .bin/.hex files?
	1.	Bootloader initializes hardware and loads firmware.
	2.	Firmware is stored as .bin (raw binary) or .hex (ASCII text with address info).
	3.	Bootloader loads these files from storage/network.

04. What is the difference between a bootloader and the startup code (crt0)?
    They are two distinct pieces of code that run sequentially.
    1.  Bootloader: Runs first. It decides if a valid application exists and where it is, then loads it and jumps to it. Its main job is firmware management.
    2.  Startup Code: Is part of the application itself. It runs after the bootloader jumps to the application. Its job is to set up the C runtime environment (stack, .data, .bss) before calling main().

05. What is a "primary" vs. a "secondary" bootloader?
    1.  Primary Bootloader (or ROM Bootloader): A small, unchangeable bootloader programmed into the chip's ROM by the silicon manufacturer (e.g., ST, NXP). It provides a basic, failsafe way to program a blank chip, usually over a specific interface like UART or USB.
    2.  Secondary Bootloader: This is the bootloader we typically develop. It's programmed into the Flash memory and runs after the primary bootloader (or directly on reset). It contains the custom logic for application updates, security checks, etc.

06. What are the key features of a robust bootloader?
    1.  Reliability: It must be the most stable piece of code on the device.
    2.  Failsafe: It must be able to recover from a failed or interrupted update to prevent "bricking" the device.
    3.  Security: It must validate the authenticity and integrity of new firmware.
    4.  Simplicity: It should do one job (update firmware) and do it well, without complex features.

07. How do you partition the Flash memory for a bootloader and an application?
    1.  This is done in the linker scripts. You need two separate linker scripts: one for the bootloader and one for the application.
    2.  The bootloader linker script places the bootloader's code at the start of Flash (e.g., 0x08000000).
    3.  The application linker script places the application's code at an offset, immediately after the bootloader's reserved space (e.g., 0x08008000).

08. What information would you put in a firmware metadata structure?
    1.  Magic Number: To identify it as a valid firmware image.
    2.  Image Size: Total size of the firmware in bytes.
    3.  CRC/Checksum: To verify integrity.
    4.  Version Number: (e.g., major, minor, patch).
    5.  Timestamp: Build date/time.
    6.  Target Hardware ID: To ensure the firmware is for the correct product.
    7.  (Optional) Digital Signature: For security.

09. What are the basic steps to write new firmware to Flash memory?
    1.  Unlock: The Flash control registers must be unlocked by writing a specific key sequence.
    2.  Erase: Flash can only be written to if it's in an erased state (all bits are '1'). You must erase entire pages or sectors at a time.
    3.  Program: Write the new data, typically in words or half-words.
    4.  Verify: Read back the data to ensure it was written correctly.
    5.  Lock: Re-lock the Flash control registers to prevent accidental writes.

10. What are the two specific CPU registers that must be manually set before a jump on Cortex-M?
    1.  MSP (Main Stack Pointer): To ensure a valid stack for the app.
    2.  PC (Program Counter): To point to the Reset Handler of the app.

11. What is a "Scatter File" or Linker Script?
    A file that defines the memory map. It tells the linker strictly where the Bootloader ends and where the Application begins.

12. What is the .isr_vector section?
    The specific linker section where the interrupt vector table is placed, usually at the very beginning of the binary.

13. Explain "A/B Partitioning" (Dual Bank).
    Flash is split into two equal slots (A and B). App runs from A; update downloads to B. On reboot, if B is valid, the bootloader swaps them (or updates a flag to boot B).

14. What is the main advantage of A/B Partitioning?
    1.  Power-Fail Safety: If power cuts during update, the old App is still valid.
    2.  Rollback: Can easily revert to the previous version.

15. What is the disadvantage of A/B Partitioning?
    Cost: Requires 2x the flash memory space.

16. What is the "Swap Scratch" method?
    Used in single-bank MCUs to simulate dual-bank. It uses a small sector (scratch) to swap the new firmware and old firmware chunk-by-chunk.

17. What is "Delta" or "Differential" update?
    Transmitting only the binary difference (diff) between the old and new version to save bandwidth. The bootloader patches the binary in place.

18. What is a "Golden Image"?
    A factory-programmed, read-only backup of the firmware. If the main App is corrupted and the update fails, the system reverts to the Golden Image.

19. What is "Background OTA"?
    The Application downloads the new firmware to an external flash/Bank B while running normal tasks. The Bootloader is only invoked for the final swap/verify.

20. What is a Hash (SHA-256)?
    A one-way function to generate a unique fingerprint of the firmware. The signature is created by encrypting this hash.

21. What is "Brown-out Detection" relevance?
    If voltage drops during a flash write, the bit might not flip correctly. The bootloader should enable BOD to reset immediately if voltage dips to prevent data corruption.

22. Why use a "Shared Memory" struct?
    A fixed RAM location known to both Bootloader and App to share version info, update status, and reset reasons.

23. What is the difference between Soft Reset and Hard Reset?
    Hard reset clears all registers. Soft reset jumps to reset vector but might leave peripherals (USB, DMA) active.

24. Why are interrupts usually not used inside the bootloader communication loop?
    To keep it deterministic and simple. Polling is often preferred to avoid stack complexity and interrupt vector management issues.

25. What is the role of the Linker .bss section initialization?
    The bootloader startup code must zero out the .bss (uninitialized variables) section, otherwise, variables will have random values.

26. Can you update the Interrupt Vector Table?
    Yes, it is just data at the start of the binary. The new binary brings its own new vector table.

27. What is a "Combined Image"?
    A single hex file containing Bootloader + App + Config, used for manufacturing programming.
