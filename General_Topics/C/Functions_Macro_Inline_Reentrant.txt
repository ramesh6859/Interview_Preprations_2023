1.	Macro functions are expanded by the preprocessor before compilation.
2.	Inline functions are handled by the compiler. 
3.	Reentrant functions are designed for safe repeated or concurrent use.
----------------------------------------------------------------------------------------------------------
----------------------------------------------------------------------------------------------------------
Macro Functions
1.	Macro functions are expanded as pure text substitution by the preprocessor before compilation, meaning the code is literally pasted into the source wherever the macro is used.
	Example:
		#define SQUARE(x) ((x)*(x))
		int y = SQUARE(3+1); // becomes ((3+1)*(3+1)) => 4*4 = 16
2.	Expressions passed as arguments to macro functions can be evaluated more than once due to text substitution, which might cause unexpected behavior or side effects.
	Example:
		int a = 5;
		int b = SQUARE(a++); // Expands to ((a++)*(a++)), which increments 'a' twice!
3.	Macro functions do not enforce parameter data type checking, as types are not known to the preprocessor:
	Example:
		#define ADD(x, y) ((x)+(y))
		// Can call ADD("5", 10) without error, but this may fail at runtime.
4.	Macros are hard to debug because the source code doesn’t show the macro expansion, making tracing and debugging difficult.
	Example:
		If there’s a bug inside a macro, you cannot easily set breakpoints or step through code.
----------------------------------------------------------------------------------------------------------
----------------------------------------------------------------------------------------------------------
Inline Functions
1.	Inline functions are expanded by the compiler as a hint to replace calls with the function’s code, but this is not guaranteed; the compiler makes the final decision.
	Example:
		inline int max(int a, int b) { return (a > b) ? a : b; }
		int z = max(10, 15);
2.	Expressions passed to inline functions are evaluated only once, reducing side effects compared to macros.
	Example:
		inline int square(int x) { return x * x; }
		int val = square(a++); // 'a' is incremented only once.
3.	Inline functions enforce strict type checking according to the language’s rules, making them safer than macros.
	Example:
		Passing incorrect types to an inline function, like max(5, "hello"), results in a compile-time error.
4.	Inline functions are easier to debug, as they are part of the actual source code, making error tracing straightforward and allowing the use of breakpoints.
----------------------------------------------------------------------------------------------------------
----------------------------------------------------------------------------------------------------------
Reentrant Functions
1.	A function is reentrant if it can safely be interrupted in the middle of its execution and re-entered before previous executions complete, often by another thread or interrupt, without losing its data integrity or resulting in incorrect outcomes.
	Example:
		int sum(int x, int y) { return x + y; }
		// This function is reentrant because it does not modify any shared/global state.
		
2.	The interruption can be caused by an external event, such as a signal or hardware interrupt, or by an internal event (such as a recursive function call).
	Example Use-case:
		If a hardware timer interrupt triggers a call to sum() while sum() is already running in a different thread or context, both calls complete safely.

3.	Upon re-entry, the function resumes from where it was interrupted and continues to completion, provided it doesn’t rely on shared global states or static variables unprotected by synchronization mechanisms.
	Non-Example:
		int count = 0;
		int inc() { return ++count; }
		// Not reentrant, as it modifies a shared global variable.
	Safe Example with Local Variables:
		int multiply(int x, int y) {
			int result = x * y; // Only stack variables used
			return result;
		}
		// This is reentrant since no global or static data is changed.
