Memory Layout and Storage Classes in C
1.	Code (Text) Segment: Stores compiled instructions (functions, program logic) in a read-only area.
2.	Initialized Data Segment (.data): Holds global and static variables initialized with nonzero values.
3.	Uninitialized Data Segment (.bss): Stores global and static variables without explicit initialization (zero by default).
4.	Heap: Provides memory for dynamically allocated variables at runtime (using malloc, calloc, etc.).
5.	Stack: Stores local automatic variables, function arguments, return addresses; grows and shrinks with function calls.

Detailed Explanation of Each Memory Segment
1.	Code Segment (.text)
	1.	Contains the executable program instructions (machine code).
	2.	Read-only to prevent accidental overwrites.
	3.	May also include constants (const variables).
	4.	On embedded systems, code resides in non-volatile memory (Flash) but may be copied to RAM for faster execution.
	5.	Example: The compiled instructions of main() and all functions are stored here.
2.	Initialized Data Segment (.data)
	1.	Stores all global variables and local static variables explicitly initialized to values not equal to 0.
	2.	Divided into:
		1.	Read-only section: e.g., const int x = 5;
		2.	Read-write section: e.g., int a = 10;
	3.	At program startup, this segment is copied from Flash/ROM to RAM.\
	4.	Lifetime: Exists for the entire program execution.
3.	Uninitialized Data Segment (.bss)
	1.	Holds global and static variables declared without explicit initialization or initialized to 0.
	2.	Automatically initialized to zero at program startup (by boot code).
	3.	Does not need to be stored in Flash/ROM since initial values are all zero.
4.	Heap
	1.	Used for dynamic memory allocation at runtime.
	2.	Grows upward in memory, starting after the data segment.
	3.	Unlike static allocation, exact size is not needed at compile time.
	4.	Managed via library functions:
		1.	malloc() / calloc() – allocate new memory
		2.	realloc() – resize allocated block
		3.	free() – release allocated block
	5.	Use Cases:
		1.	Data that must outlive the function in which it was created.
		2.	Situations where large or variable-sized memory is required.
	6.	Pitfalls:
		1.	Memory leaks if free() is not called.
		2.	Allocation failures when requests exceed available memory.
		3.	Slower execution in embedded/real-time systems.
		4.	Fragmentation and overhead due to memory management metadata.
5.	Stack
	1.	Organized as a LIFO (Last In, First Out) structure.
	2.	Stores:
		1.	Local automatic variables (int x = 5; inside a function)
		2.	Function call return addresses
		3.	Function arguments
		4.	Saved registers
	3.	Each function call creates a stack frame for its execution context.
	4.	Grows downward in memory (towards lower addresses).
	5.	Usage in Microprocessors:
		1.	Critical for control flow correctness.
		2.	Mismanagement can cause stack overflows, overwriting variables, and corrupted return addresses.

Storage Classes in C
1.	Automatic (auto)
	1.	Default for local variables inside functions.
	2.	Stored on stack, destroyed when block ends.
	3.	Value is undefined if not initialized.
	Example:
		auto int x = 0;  // stored in stack
2.	Static (static)
	1.	Retains value between function calls.
	2.	Stored in .data (if initialized) or .bss (if uninitialized).
	3.	Lifetime: Entire program execution.
	Example:
		static int counter = 0;
3.	Register (register)
	1.	Suggests storing variable in CPU registers (fastest, not guaranteed).
	2.	Size limited to machine registers.
	3.	Exists only in block scope.
	Example:
		register int i = 0;
4.	External (extern)
	1.	Declares a global variable defined elsewhere (possibly another file).
	2.	Enables sharing across multiple files/modules.
	3.	Default linkage for global variables is external unless specified static.
	Example:
		extern int data;
	4.	Footnote
		If no storage class specifier is provided for a global variable, it defaults to external linkage. Declaring with static makes the variable have internal linkage, restricting its scope to the current translation unit.
