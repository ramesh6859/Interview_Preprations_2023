MODBUS is a widely used communication protocol in embedded systems, especially in industrial automation. It supports multiple transmission modes—MODBUS ASCII, RTU, and TCP and uses a structured message format with fields like Address, Function Code, Data, and CRC/LRC. It enables communication between master and slave devices over serial or Ethernet networks. It’s simple, robust, and widely adopted in industrial embedded systems.

MODBUS Transmission Modes
1.	MODBUS RTU (Remote Terminal Unit)
	1.	Format: Binary
	2.	Efficiency: High (compact frame)
	3.	Frame Delimiters: Silent intervals (3.5 character times between frames)
	4.	Error Check: CRC (Cyclic Redundancy Check)
	5.	Use Case: RS-485/RS-232 serial links
2.	MODBUS ASCII
	1.	Format: ASCII characters (each byte as two ASCII characters)
	2.	Efficiency: Lower than RTU
	3.	Frame Delimiters: Start with colon : and end with carriage return-line feed (CRLF)
	4.	Error Check: LRC (Longitudinal Redundancy Check)
	5.	Use Case: Legacy systems or noisy environments
3.	MODBUS TCP
	1.	Format: Encapsulated MODBUS message over TCP/IP
	2.	Efficiency: High, supports multiple simultaneous connections
	3.	Error Check: TCP/IP stack handles error checking
	4.	Use Case: Ethernet-based embedded systems

MODBUS Message Structure (Frame Format)
1.	Address: Identifies the slave device (1–247 for RTU/ASCII; TCP uses Unit Identifier)
2.	Function Code: Specifies the operation (e.g., Read Coils = 0x01, Write Register = 0x06)
3.	Data: Contains request parameters or response values
4.	CRC/LRC: Error checking (CRC for RTU, LRC for ASCII)

MODBUS RTU Frame Example
[Slave Address][Function Code][Data][CRC]
Example: 01 03 00 00 00 02 C4 0B
	01: Slave ID
	03: Read Holding Registers
	00 00: Starting address
	00 02: Number of registers
	C4 0B: CRC
	
MODBUS ASCII Frame Example
: [Address][Function][Data][LRC] <CR><LF>
Example: :010300000002F9<CR><LF>
	:: Start
	01: Slave ID
	03: Function
	00000002: Data
	F9: LRC
	
MODBUS TCP Frame Example
[Transaction ID][Protocol ID][Length][Unit ID][Function][Data]
Example: 00 01 00 00 00 06 01 03 00 00 00 02
	00 01: Transaction ID
	00 00: Protocol ID
	00 06: Length
	01: Unit ID
	03: Function
	00 00 00 02: Data

CRC vs LRC
	CRC (RTU): 16-bit polynomial-based error check
	LRC (ASCII): 8-bit checksum of all bytes between : and LRC
